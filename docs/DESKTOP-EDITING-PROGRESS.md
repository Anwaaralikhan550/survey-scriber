## D4 design notes
- Photos are the survey's `Media` rows (type PHOTO), not content blocks: one source of truth for phone and browser. `sectionKey` = the cloud section key (`<sectionKey>/<screenId>`), `sortOrder` per section, `caption`.
- Every photo change = one transaction on the locked report row: version check (`expectedReportVersion`), change, version+1, history row (reason PHOTO), audit event. The text editor takes the new version from the reply (`editor.syncVersion`) so text and photo saves never conflict with each other.
- Replace = new photo (new id, so no cache shows the old picture) with the old caption/section/place, old one marked deleted in the same step; a failed replacement leaves the old photo and no stray file. Delete = soft delete (`deletedAt`), file kept; the owner list `includeDeleted=true` tells the phone what to remove.
- Photo file reads are exempt from the global rate limit (a grid asks for many at once); client retries 429 politely for everything else.
- Phone side limits: photo -> section mapping uses the app's media `sectionId` == report screen id (works when photos are taken inside a screen; otherwise the photo shows as "No section" in the browser). Annotations stay local (vector JSON, never sent); a replaced photo on the phone loses its annotations because it is a new photo. Captions are not printed by the existing PDF/Word renderers (client has not asked).
- Browser-test infra notes: backend `storage/` folder holds uploaded files (test photos in `backend/storage/<surveyId>`); `tmp/desktop-editing/fixtures/` is generated by `p21_photos.js` and needed by the Flutter real test.

## D3 design notes
- One cloud section per report screen (key `<sectionKey>/<screenId>`, title `Section / Screen`), blocks: paragraph per phrase (role `phrase`), rating block (role `rating`, required) from the "Condition rating is: N." line with its explanation in `text`, the surveyor note (role `note`), and an `ACCOMMODATION` section with a table block (role `schedule`). Ids are UUIDv5 from the survey id, so re-uploads keep ids. Backend now stores `role` on blocks (editor cannot set it).
- Phone state per survey: `desktop_edit_<id>.json` (appVersion = cloud version this phone matches, synced sections) + the link address in secure storage (it is a bearer secret). Upload needs `appVersion == cloudVersion` (never overwrite unseen browser edits); after a Synchronise the next upload carries the edited wording.
- Synced edits are applied to the report at export time and replace the wording of the screens the editor changed. If answers change afterwards the edited wording still wins for those screens until the owner taps "Remove edited wording" (shown on the screen).
- API allows 3 requests/second per IP, so each action sends at most 2 requests and updates the screen from the replies; 429 is mapped to a friendly message.
- Level 3 does not exist as an app type; reportType sent is `L2` for inspections.

## D2 design notes
- Editor state (`src/useEditor.js`): server copy + working copy; pending changes are computed by `diffContent(server, working)` (`src/diff.js`), so undo/redo is just snapshots and a save sends the diff as spec-style ops (updateBlock/addBlock/deleteBlock/moveBlock). Added `atStart` placement to the backend for add/move to index 0.
- Save states: saved / unsaved / saving / failed / offline / conflict / readonly / lost. "Saved" only after the server confirmed and the report was re-read. Retries reuse one idempotency key. A failed save is never repeated automatically; during conflict save is blocked until the user chooses (re-apply or discard).
- Backend additions in D2: `POST /editor/close` (exit ends only that session), editor read includes `property` (reference, address), `X-CSRF-Token` allowed by CORS, open-link rate limits configurable by env `EDITOR_OPEN_LIMIT_PER_SECOND/MINUTE/HOUR` (defaults 3 / 10 / 30 per IP).
- Test server for the browser test: backend `node dist/src/main.js` on :3099 with env from the E2E harness plus raised open limits, DB `ss_desk`; editor `npx vite preview` on :5174 (proxies /api). Playwright uses system Chrome (`channel: 'chrome'`); test JWT secret is `e2e-local-only-access-secret-...` (Prisma loads backend/.env into process.env, so the test must not read JWT_ACCESS_SECRET from env). Space helper requests >= 450 ms: global API limit is 3 requests/s per IP.
- Known gaps by design, done later: photo panel (D4), review/submit button (D5), AI panel (D6); frame-ancestors/CSP headers from nginx (D8).
